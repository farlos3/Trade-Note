# Deploying TradeNote on Render

The app (Express + Parse Server) runs on Render; the database is MongoDB Atlas; MetaTrader 5
stays on your Windows machine and **pushes** to the app over HTTPS. Nothing about MT5 is
deployed. Blueprint: [render.yaml](../render.yaml) (Docker, Singapore, free plan).

```
MT5 terminal (your PC) → mt5_sync.py + mt5_live.py → HTTPS → Render app → Atlas
                                                    browser ←───────┘
```

## Before you deploy (do these first)

- [ ] **GitHub repo is private** (Settings → General → Danger Zone). It holds your setup images
      and history; Render can deploy a private repo once you connect GitHub.
- [ ] **Git history is clean and pushed.** `notebook/` (personal trading data) was removed from
      history locally; GitHub still has the old history until `git push --force-with-lease origin main`.
- [ ] **Backups are in a private bucket.** `R2_BACKUP_BUCKET` (private) must exist and hold the
      backups, and `R2_BUCKET` (public, for screenshots) must hold none (see "R2" below).
- [ ] **Atlas cluster is running** (M0 pauses when idle; only the Atlas UI can resume it) and Network
      Access allows `0.0.0.0/0` (Render's IPs are not fixed).
- [ ] You know the password of your TradeNote login (`farlos@tradenote.lock`). The user already
      exists in Atlas, so you simply log in; `TRADENOTE_USER/PASSWORD` stay blank on Render.

## Deploy

1. Render → **New + → Blueprint** → connect the repo → it reads `render.yaml`.
2. Fill the prompted secrets (copy from your local `.env`; never paste them in chat):

   | Render variable | From `.env` | Note |
   |---|---|---|
   | `MONGO_URI` | `ATLAS_APP_URI` | must end `.../tradenote?...` — **without the db name every login fails** |
   | `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_PUBLIC_URL` | same names | the PUBLIC bucket only |
   | `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` | — | **create a separate R2 token for Render**, Object Read & Write on `R2_BUCKET` only, so a leaked Render env cannot touch the backups |
   | `GEMINI_API_KEY` / `ANTHROPIC_API_KEY` | same names | optional (AI Analysis) |
   | `TRADENOTE_USER`, `TRADENOTE_PASSWORD` | — | leave blank |

   `APP_ID` and `MASTER_KEY` are generated by Render (long, random). Do **not** copy the local ones.
3. Wait for the build (about 5 minutes) and for the health check on `/` to go green.
4. Open `https://<service>.onrender.com`, log in, open **Settings → MT5 accounts allowed to sync**
   and confirm both accounts are listed (that list lives in the database, so it is already there).

## Point MT5 at it

On the Windows machine:

1. `mt5-sync/config.ini` → `[tradenote] url = https://<service>.onrender.com` (same `api_key`).
   Keep `[mt5] broker_dst = eu` for HFMarkets.
2. **Stop the local app**: `docker compose -f docker-compose-dev.yml stop tradenote`. Only one app may
   receive the sync (the import queue only protects within one process).
3. `mt5-sync/mt5-agent.sh start` — checks the target and api key, checks the MT5 account is allowed,
   syncs once, (re)starts the live feed. `mt5-agent.sh status` shows where it points and what runs.
   The every-minute sync is the scheduled task "TradeNote MT5 sync"; it reads `config.ini` on every run.
4. Do **not** use `./tradenote.sh start` for this: it also brings up the local app.

Works only while the machine is on and MT5 is open and logged in. After downtime the sync refills the
gap by itself (up to `max_catchup_days`, default 90).

## Verify

- [ ] `mt5-agent.sh status` → "Reachable, api key accepted", live feed running.
- [ ] Live page shows the open position (give a free instance ~1 min to wake first).
- [ ] After the next closed trade, the Dashboard on the Render URL shows it.
- [ ] `python mt5-sync/reconcile.py --days 14` → `IN SYNC`.
- [ ] Logged out (private window), `/api/live` and `/api/journal/version` answer 401.

## Free plan behaviour

Sleeps after 15 min without a request; the first request then waits ~30–60 s. While MT5 is open the
sync (every minute) and live feed (every second) keep it awake. The live feed is held in memory only,
so after a wake-up the Live page is empty until MT5 pushes again. Switch `plan:` to `starter` if that
becomes a nuisance.

## Roll back

Set `url = http://localhost:8080` in `config.ini` and `docker compose -f docker-compose-dev.yml up -d tradenote`
(`NODE_ENV=prod` for the bundled build). Same Atlas database, nothing to migrate.

## Troubleshooting

| Symptom | Cause |
|---|---|
| Health check fails / every path 404 | `MONGO_URI` wrong or missing `/tradenote`; Atlas cluster paused; Network Access not open |
| Login fails right after deploy | same as above (reads the empty default database) |
| `mt5-agent.sh`: HTTP 401 | `api_key` in `config.ini` is not the TradeNote key of that user (Settings → API Keys) |
| `mt5-agent.sh`: account not allowed / HTTP 403 | add the account in Settings → MT5 accounts allowed to sync |
| "Cannot reach" | service asleep (it waits up to 90 s), wrong url, or not deployed |
| Live page empty | agent not running (`mt5-agent.sh status`), or MT5 closed |

## R2: two buckets

`R2_BUCKET` is public (the browser loads screenshots from `R2_PUBLIC_URL`) and R2 makes a bucket public as a
whole. Database backups used to live in it under `data/`, readable by anyone, including the `_User`
collection (api keys, password hash, balances). Backups now go to `R2_BACKUP_BUCKET`, a **private** bucket
(no r2.dev URL, no custom domain); the backup scripts refuse to run if it equals `R2_BUCKET`.
Check any time: `curl -I <R2_PUBLIC_URL>/data/tradenote/latest/_User.parquet` must NOT return 200/206.
